> [!IMPORTANT]
> **本项目的代码、测试和文档均完全通过 OpenAI GPT 与 Codex 完成。**
>
> 项目需求定义、功能取舍、真实思源环境测试、结果验收与发布决策由 Yong Sheng 负责。

思源笔记滴答任务中心是一个思源笔记插件，用于把普通思源文档块关联到 TickTick / 滴答清单任务。原文档中的任务块是唯一持久化数据源；插件在其上提供任务卡片增强、七种本地状态、四种工作分类、截止日期提醒、每日推进记录和全工作空间任务中心，不会维护第二套任务数据库。

当前版本不使用 TickTick API、OAuth 或后台同步。任务与 TickTick / 滴答清单的关联仅依靠用户提供的 HTTPS 任务链接。

**本项目是社区开发的非官方插件，与 TickTick、滴答清单及思源笔记官方无隶属关系。**

## 核心功能

- 在可编辑的思源文档中，通过斜杠菜单创建 TickTick 任务块；默认状态为 `in-progress`，新块插入当前根文档顶部。
- 在一个普通思源块中保存任务标题、经过校验的 TickTick URL、七项必需属性，以及可选的工作分类、截止日期和每日推进日期属性。
- 在原始块中保留包含标题和链接的普通 Markdown；插件关闭时仍可阅读和打开链接。
- 在文档内非破坏性地增强显示任务卡片，包括可打开任务中心的插件自有清单图标、任务链接、工作分类按钮、带语义颜色的状态徽章和 Deadline 按钮；工作分类固定显示在状态上方。
- 点击工作分类、状态或 Deadline 按钮打开完整编辑窗口，可修改标题、URL、工作分类、状态和截止日期；工作分类与状态均使用平铺按钮直接选择。
- 在文档任务卡片或任务中心条目的任意位置右键，可编辑任务或经二次确认后删除思源任务卡片；删除不会影响 TickTick / 滴答清单中的实际任务。
- Deadline 按钮以剩余天数、8 格紧迫度条和具体日期显示任务期限；未设置截止日期时保留一致轨道并提供明确入口。
- 距离截止日期大于 7 天时保持空轨道；从剩余 7 天开始逐日填充，今天截止和已经逾期时显示满格。
- 活跃任务进入 7 天期限窗口后使用主题自适应的低饱和提醒色；今天截止使用警告色，逾期使用错误色，同时保持主题文字和按钮对比度。
- 编辑时保持 `created-at` 不变，只在数据真实变化时更新 `updated-at`。
- 保存前检查 `updated-at` 冲突，避免覆盖其他位置产生的更新；标题或 URL 双写失败时尝试回滚 Markdown。
- 从思源顶栏打开单例任务中心页签，动态汇总整个工作空间中的有效任务。
- 插件首次启用时默认使用中文；可在任务中心刷新按钮左侧切换中英文界面，选择会持久保存。
- 支持活跃、已结束和全部任务筛选，以及任务标题、来源文档、来源路径和本地化状态搜索。
- 显示全部、活跃、已结束和今日进度统计；普通列表按任务属性中的 `updated-at` 降序稳定排列。
- 在活跃任务视图中显示“🌤️ 今日待推进”和“✨ 今日进展”；今日进展进一步区分“🚀 已推进”和“🏆 今日完成”。
- “今日待推进”强制按截止日期从近到远排列，逾期任务最先、未设置截止日期的任务最后；日期相同时再按更新时间降序排列。
- 待开始、进行中、等待回复和已阻塞任务都参与每日推进；任务切换为已完成时自动记录为今日进展。
- 使用 `🚀 今日推进` 和 `✨ 今日已推进` 标记或撤销当天记录，不改变任务状态和原有 `updated-at`。
- 按系统本地时区判断“今天”，跨过本地午夜后自动重新分组，不需要后台批量重置属性。
- 支持定位原始思源任务块，并安全地在新标签页打开对应 TickTick 任务链接。
- 在任务中心内编辑任务后立即更新当前列表、筛选结果、排序和统计。
- 普通文档或其他客户端产生的变化由用户通过任务中心的“刷新”按钮读取。

## 七种任务状态

状态 ID 是持久化与查询使用的稳定值；Emoji 和显示文字只用于界面展示。

| Key | 中文 | English | 类型 |
| --- | --- | --- | --- |
| `todo` | ⚪ 待开始 | To do | 活跃 |
| `in-progress` | ▶️ 进行中 | In progress | 活跃 |
| `waiting` | ⏳ 等待回复 | Waiting for response | 活跃 |
| `blocked` | ⛔ 已阻塞 | Blocked | 活跃 |
| `completed` | ✅ 已完成 | Completed | 已结束 |
| `failed` | ❌ 已失败 | Failed | 已结束 |
| `cancelled` | ⏹️ 已取消 | Cancelled | 已结束 |

## 四种工作分类

工作分类描述任务采用的工作方式，与任务当前状态相互独立。分类 ID 保存于思源块属性，Emoji 和中英文名称只用于界面展示。

| Key | 显示名称 | 含义 |
| --- | --- | --- |
| `explore` | 🔭 探索-Explore | 调研、学习、论证可行性或寻找方向，结果和耗时可能不确定 |
| `build` | 🛠️ 构建-Build | 将已经确定的方法、推导或设计实现为代码、工具或流程 |
| `execute` | ⚙️ 执行-Execute | 使用成熟工具和既定流程完成分析或交付 |
| `review` | 🔎 评审-Review | 检查实现或结果、提出反馈并作出判断，例如 PR Review |

## 安装

### 普通用户安装

本插件目前尚未上架思源集市，GitHub 仓库也尚未发布可供普通用户下载的 Release。

发布版本将通过 [GitHub Releases](https://github.com/Yong2Sheng/siyuan-plugin-ticktick-task-center/releases) 提供；在首个 Release 发布前，可使用下面的开发安装方式。请不要把 GitHub 自动生成的 Source code 压缩包当作思源插件包。

### 开发安装

开发环境以项目的 CI 配置为准：Node.js 24、pnpm 11.7.0，以及思源桌面版 3.7.0 或更高版本。当前主要在 macOS 桌面版思源中开发和验收；HarmonyOS 原生移动端已在运行 HarmonyOS 6 的华为平板上完成核心功能基础验证，但仍属于实验性支持。Android、iOS 和浏览器移动端尚未验证。

确保思源正在运行，然后执行：

```bash
git clone https://github.com/Yong2Sheng/siyuan-plugin-ticktick-task-center.git
cd siyuan-plugin-ticktick-task-center
corepack enable
pnpm install
pnpm make-link
pnpm dev
```

`pnpm make-link` 会尝试读取当前思源工作空间，并把开发输出目录链接到该工作空间的插件目录；无法自动发现时，可通过 `SIYUAN_PLUGIN_DIR` 指向目标工作空间的 `data/plugins` 目录。

`pnpm dev` 是持续运行的监听构建进程。源码变化后 watcher 会重新生成开发 bundle；如思源没有自动载入最新 bundle，请关闭并重新启用插件。

执行 `pnpm build` 后，也可以将仓库根目录生成的 `package.zip` 解压到：

```text
<思源工作空间>/data/plugins/siyuan-plugin-ticktick-task-center/
```

确保 `plugin.json` 直接位于上述目录中，然后完全重启思源。也可以在思源运行时执行 `pnpm make-install`，选择当前工作空间后自动构建并覆盖安装。

## 使用方法

### 1. 创建任务

1. 打开一个普通、可编辑的思源文档。
2. 输入 `/` 打开 Protyle 斜杠菜单。
3. 搜索并选择“滴答任务卡片”（英文界面为 “TickTick task card”）。
4. 确认或修改任务标题。插件会尝试以当前根文档标题作为默认值。
5. 粘贴合法的 TickTick / 滴答清单 HTTPS URL。当前只接受主机名精确为 `ticktick.com` 或 `dida365.com` 的链接。
6. 选择任务状态；默认状态为 `in-progress`（▶️ 进行中）。
7. 从四个平铺按钮中选择工作分类；新任务必须明确选择一项，不自动推断。
8. 根据需要设置截止日期；该字段可以留空，也可以稍后补充或清除。
9. 点击“创建”。
10. 新任务会作为当前根文档的第一个子块插入，也就是位于文档标题下方、其他正文之前，并立即增强显示为任务卡片。

### 2. 在文档中编辑任务

- 点击任务卡片右侧纵向按钮组上方的工作分类，打开完整编辑窗口并聚焦工作分类。
- 点击工作分类下方的状态徽章，打开同一个编辑窗口并聚焦任务状态。
- 点击最右侧的 Deadline 按钮，打开同一个编辑窗口并聚焦截止日期字段。
- 工作分类和任务状态均直接展示全部选项，点击即可选择，不使用下拉菜单。
- 修改任务标题、TickTick URL、工作分类、任务状态或截止日期，然后保存。
- 保存成功后，当前文档中的卡片立即更新。
- 标题或 URL 变化时，底层 Markdown 降级内容同步更新。
- 状态不会写入 Markdown，而是以稳定状态 ID 保存在结构化属性中。
- `created-at` 保持不变；只有实际发生修改时才生成新的 `updated-at`。

### 3. 使用 Deadline 提醒

- Deadline 使用本地日历日期，不包含具体时刻；显示和计算均跟随电脑当前时区。
- 按钮第一行显示“剩余 N 天”“今天截止”“逾期 N 天”或“无截止日期”，第二行固定显示 8 格轨道，第三行显示具体日期或设置入口。
- 剩余时间大于 7 天及未设置日期时，8 格轨道保持低对比度空格。
- 剩余 7 天时填充第 1 格，随后每天增加 1 格；剩余 1 天时填充 7 格，今天截止和逾期时填满 8 格。
- 截止日期只保存在思源任务块属性中，不会写回 TickTick，也不会创建系统通知或后台提醒。

### 4. 打开任务中心

- 点击任一文档任务卡片左侧的清单图标，或点击思源顶栏中的滴答任务中心按钮。
- 任务中心以独立自定义页签打开。
- 同一时间只存在一个任务中心页签；再次点击卡片图标或顶栏按钮只会聚焦已有页签。
- 页签首次打开时会查询一次当前工作空间中的任务。

### 5. 使用任务中心

- 点击刷新按钮左侧的 `Switch to English` 切换为英文界面；切换后按钮显示“切换为中文”，再次点击即可恢复中文。
- 查看全部、活跃、已结束和今日进度。
- 在“活跃任务”“已结束”和“全部任务”之间切换。
- 搜索任务标题、来源文档标题、来源路径或本地化状态名称。
- 点击任务标题或“定位原块”，打开并定位对应的思源任务块。
- 点击“打开滴答任务”，在新标签页打开经过校验的外部任务链接。
- 点击任务条目的工作分类按钮，复用同一个完整任务编辑窗口并聚焦工作分类。
- 点击任务条目的状态徽章，复用同一个完整任务编辑窗口。
- 点击任务条目的 Deadline 按钮，可直接修改或清除截止日期。
- 在任务条目任意位置右键，可编辑任务或删除任务卡片；从任务中心删除成功后，当前列表立即更新，已经打开的来源文档由思源同步删除原块。
- 从任务中心保存编辑后，当前列表、筛选结果、排序和统计立即更新，无需刷新。
- “今日待推进”优先显示已经逾期和即将到期的任务，没有截止日期的任务排列在最后。

### 6. 记录今日推进

- “活跃任务”视图内部自动划分为“🌤️ 今日待推进”和“✨ 今日进展”两个区域。
- “今日进展”内部继续区分“🚀 已推进”和“🏆 今日完成”，便于同时看到仍在推进与当天完成的工作。
- 所有非终态任务都参与每日推进，包括待开始、进行中、等待回复和已阻塞；检查阻塞原因是否解除也可以视为一次推进。
- 点击 `🚀 今日推进` 后，任务移动到“今日进展”的“已推进”分区，顶部今日进度同步增加。
- 点击 `✨ 今日已推进` 可以撤销误操作，任务会回到“今日待推进”。
- 任务从非完成状态切换为“✅ 已完成”时会自动记录当天日期，并保留在“🏆 今日完成”分区；它仍属于已结束任务，不计入活跃任务数量。
- 已失败和已取消任务不会进入“今日完成”。
- 顶部今日进度的分子为今日已推进与今日完成之和，分母为今日待推进与今日进展之和，因此全部完成时仍会显示 `10 / 10`。
- 每日推进只保存最后推进日期，不会把任务改为已完成，也不会修改任务的 `updated-at` 或现有排序。
- “今天”跟随电脑当前系统时区；本地午夜后界面自动将昨日记录视为今日待推进，重新聚焦思源窗口时也会校正日期。

## 刷新与同步规则

> [!WARNING]
> **在任务中心之外创建或修改任务后，必须回到任务中心点击“刷新”，任务中心才会显示最新结果。**
>
> 任务中心不会轮询，也不会在后台自动查询普通文档中的变化。

| 操作位置 | 任务中心行为 |
| --- | --- |
| 在任务中心编辑任务 | 保存后立即更新当前任务中心列表，无需刷新 |
| 标记或撤销今日推进 | 保存后立即移动分组并更新今日统计，无需刷新 |
| 在普通文档创建任务 | 不会自动出现在任务中心；需要点击“刷新” |
| 在普通文档编辑任务 | 任务中心不会自动变化；需要点击“刷新” |
| 直接修改任务块属性 | 需要点击“刷新” |
| 在其他客户端或设备修改 | 需要点击“刷新” |
| 首次打开任务中心 | 自动查询一次 |
| 搜索或切换筛选 | 只处理当前列表，不执行 SQL |
| 任务中心空闲放置 | 不进行后台查询 |

“刷新”按钮不是故障恢复按钮，而是同步任务中心外部变化的明确入口。

在任务中心编辑或记录今日推进后立即点击刷新时，思源 SQL 索引可能暂时仍返回旧值。插件会在当前任务中心页签内保留最近编辑或推进结果，避免界面退回旧标题、URL、状态、截止日期或推进分组；当 SQL 返回对应数据，或该任务不再有效时，这个临时覆盖会被清除。它不会替代任务块属性，不会跨页签持久化，也不是第二套任务数据库。

## 数据模型与隐私

- 一个普通思源块对应一个 TickTick 任务。
- 原始思源任务块是唯一持久化数据源。
- 任务中心是动态视图，不持久化第二份任务列表。
- 普通 Markdown 保留任务标题和链接，作为插件关闭或不可用时的降级内容。
- 插件不要求登录 TickTick，不使用 OAuth，也不调用 TickTick API。
- 插件不会在后台向 TickTick 上传或同步任务数据；外部链接只在用户点击时打开。

七项必需结构化属性为：

```text
custom-ticktick-card
custom-ticktick-version
custom-ticktick-title
custom-ticktick-url
custom-ticktick-status
custom-ticktick-created-at
custom-ticktick-updated-at
```

每日推进使用一个可选属性：

```text
custom-ticktick-last-progressed-date = YYYY-MM-DD
```

截止日期使用另一个可选属性：

```text
custom-ticktick-deadline = YYYY-MM-DD
```

工作分类使用可选属性保存稳定分类 ID：

```text
custom-ticktick-work-mode = explore | build | execute | review
```

老任务没有这些可选属性时无需迁移：没有每日推进日期时直接视为今日待推进，没有截止日期时显示“无截止日期”并在 Deadline 排序中置后，没有工作分类时显示“未分类-Unclassified”。再次编辑旧任务时需要明确选择工作分类。插件只比较保存日期与系统本地日期，不在午夜批量改写任务块。

## 任务中心查询

任务中心每次加载或手动刷新时执行一次全局 SQL 查询。七项必需任务属性以及可选的工作分类、每日推进和截止日期属性通过条件聚合转换为每个任务一行，避免旧式“一项属性一行”的结果在思源 SQL 查询数量上限处产生属性不完整的半个任务。

查询仍受思源全局 SQL 结果数量上限约束，当前没有分页。搜索和分类只处理已经加载并通过验证的内存结果，不会额外执行 SQL。

## 已知限制

- 普通文档、其他页签或其他客户端中的变化不会自动推送到任务中心，需要手动刷新。
- 不支持 TickTick API、OAuth 或双向同步。
- 不支持批量操作或批量状态修改。
- 任务中心没有分页和虚拟滚动，并受思源 SQL 结果数量上限约束。
- 没有设置页面。
- 每日推进只保存最近一次日期，不提供历史记录、连续天数或趋势统计。
- 每日日期跟随系统当前时区；跨时区旅行时，任务会按照所在地的本地日期重新判断。
- Deadline 是思源中的本地元数据，不会读取或同步 TickTick 中已有的截止日期，也不会触发系统通知。
- 工作分类是思源中的本地元数据，不会自动创建或同步 TickTick / 滴答清单标签。
- HarmonyOS 原生移动端已在运行 HarmonyOS 6 的华为平板上通过核心功能基础验证，但仍属于实验性支持；Android、iOS 和浏览器移动端尚未验证。
- 移动端的跨应用链接行为取决于系统、浏览器和目标应用：TickTick / 滴答清单链接可能先在网页中打开，外部应用中的 `siyuan://blocks/...` 链接也可能无法直接唤起思源并定位块。

## 开发与验证

```bash
pnpm install
pnpm dev
pnpm test
pnpm run check
pnpm build
```

- `pnpm dev`：启动开发监听构建，需要持续运行。
- `pnpm test`：运行 Vitest 自动测试。
- `pnpm run check`：运行 Svelte / TypeScript 静态检查。
- `pnpm build`：生成生产 bundle、`dist/` 和根目录下的 `package.zip`。

当前验证规模为 23 个测试文件、225 项测试。
