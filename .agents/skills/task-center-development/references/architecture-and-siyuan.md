# 架构、数据与思源 API 参考

仅在任务涉及任务数据、知识索引、持久化、查询或直接访问思源空间时读取。

## 主要职责

- `src/index.ts`：插件生命周期、思源入口、页签/对话框编排和顶层依赖装配。
- `src/domain/`：任务、状态、工作分类、目标链接、截止日期、本地日期和思源 ID 等纯领域规则。
- `src/task-card/`：任务卡片的创建、编辑、删除、数据解析、渲染、生命周期和提交控制。
- `src/task-center/`：全空间 SQL 查询、数据聚合、筛选、控制器、页签和视图。
- `src/knowledge/`：知识文档扫描、可重建索引、复习调度、控制器和视图。
- `src/siyuan/api.ts`：思源官方 API 的统一响应码和错误边界。
- `src/siyuan/blocks.ts`、`documents.ts`、`sql.ts`、`navigation.ts`：块属性、文档树、SQL 和导航适配。

## 数据不变量

任务中心通过 `attributes` 与 `blocks` 查询原任务块。必须保持：

1. `custom-ticktick-*` 属性是任务标题、目标、状态、分类、时间等数据的唯一持久化来源。
2. SQL 和解析器以稳定 ID 与版本字段判断，不通过界面文字或 Emoji 推断数据。
3. 任务中心中的编辑直接更新原块；不在插件设置、缓存或视图状态中复制一份任务记录。
4. 现有任务缺少可选字段时继续有效；新增字段需要覆盖旧属性解析、创建、编辑、清除、查询和测试。
5. 编辑保存前保留现有冲突检测语义。多步写入失败时不得把部分成功伪装为完整成功，并应保留可恢复信息。
6. 知识文档的持久身份来自文档属性；索引缓存可丢弃重建，不保存文档正文。重新扫描不得清空已有复习进度。
7. 知识扫描保持手动触发，并把嵌套任务文档视为新的任务根边界。

## 直接调用思源本地 API

- 读取真实空间前确认思源正在运行。连接信息未知且默认 `127.0.0.1:6806` 不可用时，向用户询问端口和 API token。
- token 使用 `Authorization: Token <token>`，但不得显示在进度消息、测试快照、仓库文件或最终汇报中。
- 读取优先使用与问题匹配的官方接口：SQL 查询、`getChildBlocks`、`getBlockDOM`、`getBlockAttrs`、文档树、属性视图或数据库接口。
- 不调用 Markdown 导出接口来建立可回写数据，也不把 `getBlockDOM` 当成整篇文档覆盖模板。
- 直接修改真实空间之前必须取得用户明确授权。先用只读接口生成目标清单，说明要修改的对象和字段；授权后仍不得扩大目标集合。
- 写入只调用精确块级、属性视图或数据库接口。每次写入后再次读取目标并核对 ID、字段和值；批量操作需要报告成功、失败和未处理项。
- 删除、覆盖、批量变更或恢复都属于修改，使用同一授权规则。恢复优先查思源历史并选择准确版本。

## 实现新的 API 调用

1. 先检查 `src/siyuan/` 是否已有封装；不要从组件直接散落调用。
2. 使用 `requestSiYuan` 统一检查非零响应码。
3. 在外部数据进入领域层的边界验证响应形状；对异常响应抛出可定位的错误，不静默返回空数据。
4. 将纯解析和转换逻辑与网络调用分离，以便用固定输入测试。
5. 写操作测试至少覆盖成功、API 失败、部分步骤失败、冲突以及写后复核不一致。
